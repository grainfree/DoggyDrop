# OpenStreetMap data use — technical record and owner review

DoggyDrop supports source-backed imported bins, WaterPoints and Places. Importers require an existing DataSource, preserve source provenance and use reviewed duplicate/final-validation rules. This audit did not inspect production records or assert which prepared batches have actually been imported.

Prepared research/import history includes dog-waste bins, drinking-water points and dog parks from Slovenia OSM research. WaterPoint research identifies a Geofabrik Slovenia extract with source timestamp 2026-09-28 20:23:05 UTC and a proposed DataSource date 2026-09-28. That is extract/source age, not proof of physical inspection. Dataset/provenance ledgers remain external to the repository. No research CSV or production export is copied into this Epic.

Suggested/source names such as “OpenStreetMap — koši za pasje iztrebke” and “OpenStreetMap — pitniki” express origin, not a claim that OSM endorses DoggyDrop. An Admin import or approval is not a field survey. A community photograph/confirmation/correction supplements evidence; it does not replace DataSource, confer ownership, verify every attribute or automatically edit the source OSM object. WaterPoint working confirmation is not potability certification.

Public source output uses safe source metadata only. Private DataSource contact/notes stay Admin-only. Existing CARTO/OSM/Stadia map attribution and ORS route attribution remain separate from the data-source obligation and unchanged. Public records and map presentation can each have attribution requirements; one footer does not automatically settle all duties.

Owner/legal review must establish what constitutes the relevant database, whether the actual combined/modified use is a derivative or collective database, and what ODbL attribution, share-alike and access/distribution duties apply to the intended public service and municipal outputs. Manual review, community corrections or Admin approval do not automatically remove source-license obligations. Do not promise that DataSource attribution alone satisfies ODbL.

Primary references: [OSMF attribution guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines), [Produced Work guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Produced_Work_-_Guideline), [licensing FAQ](https://osmfoundation.org/wiki/Licence/Licence_and_Legal_FAQ). This is an issue register, not a legal conclusion or a new license.

No OSM upload/edit, live source query, production import, source reclassification or provenance mutation occurred in Epic 24.0. Public launch and municipal outreach remain blocked pending the owner/legal gates in privacy-legal-review.md.
